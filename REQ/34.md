## 5. Notes and risks

- The merge touched a submodule directory; after renaming `apps/stable-sl`
  run `git submodule sync` and confirm `apps/web/app/api` still points to
  `coordinator-stable-sl`.
- The snapshot `../stable-sl-pnpm11` holds a 2.1 GB `node.core` plus a 30 MB
  `chrome.core`; deleting it frees space and prevents them from being copied
  into the repository.
- pnpm 11 enables `minimumReleaseAge` (24 h) by default; if a fresh
  `@pasosdejesus/*` release is needed, add
  `minimumReleaseAgeExclude: ['@pasosdejesus/*']` instead of disabling the rule.
- If pnpm reports a workspace cycle, add `ignoreWorkspaceCycles: true` (the
  `m` monorepo needed it).
- `m:update` maps template `apps/web` / `apps/contracts` onto the legacy names
  until the rename, so template drift is harmless before 3.3 and uses the
  recommended paths afterwards.
- Do not run `pnpm test` inside an app: use the root (`pnpm -r`) or the
  package `Makefile`.
